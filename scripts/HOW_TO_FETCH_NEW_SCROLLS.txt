HOW TO FETCH NEW SCROLLS FOR THE SCRIPTURE CATALOG
====================================================
Last updated: 2026-03-06
Applies to: collectionId 48 (parts 372-537+)

UPSTREAM SOURCE
---------------
Website: https://w1.xianmijingzang.com
SSL: Use NODE_TLS_REJECT_UNAUTHORIZED=0 (their cert is expired)

KEY URLs:
  Page URL:    https://w1.xianmijingzang.com/wap/tripitaka/id/{collectionId}/subid/{subid}/
  Content API: POST https://w1.xianmijingzang.com/wapajax/tripitaka/
               Body: menuid={collectionId}|{subid}&book={bookId}&lang=zh&only_content=1
               Content-Type: application/x-www-form-urlencoded; charset=UTF-8
               Response encoding: GBK (must decode with iconv or similar)


STEP 1: GET THE CORRECT SUBID FOR EACH PART
--------------------------------------------
The subid is NOT simply sequential. There are foreign/duplicate entries in the
upstream subid sequence that must be SKIPPED:

  subid 484 = Foreign entry (Part 20 from a different collection) — SKIP
  subid 486 = Foreign entry (Part 42 from a different collection) — SKIP
  subid 573 = Duplicate of Part 478 — SKIP
  subid 633 = Part 467 (relocated to end, title: 佛說甚深大廻向經)

So from subid 484 onward, the part→subid mapping is NOT one-to-one sequential.
Use scripts/verify_subids.cjs to verify: it fetches the <title> tag from each
subid page and compares with our catalog title.

IMPORTANT: When adding new parts beyond 537, check for NEW foreign/duplicate
entries in the subid sequence. Fetch a range of subids beyond the last known
one and check their <title> tags to see if any are out-of-place.
Use scripts/check_extended_subids.cjs as a template.


STEP 2: GET firstBookId AND scrollCount FROM THE PAGE
-----------------------------------------------------
The page at each subid URL contains a list of scrolls as <li> elements:

  <li id="4059"><b>0a卷</b>...</li>
  <li id="4060"><b>1卷</b>...</li>

Extract:
  - firstBookId = the id of the FIRST <li> element (smallest number)
  - scrollCount = total number of <li> elements
  - has0aPreface = true if the first label contains "0a"

DO NOT assume bookIds are sequential across parts. Each part's firstBookId
comes from the upstream page, and there are gaps between parts.

Use scripts/verify_bookids.cjs to verify all entries.

IMPORTANT: The old approach of assuming sequential bookIds (each part =
previous part's firstBookId + previous scrollCount) is WRONG. The upstream
has gaps and non-sequential bookIds.


STEP 3: HANDLE 0a PREFACE ENTRIES
----------------------------------
Some parts have a "0a卷" (preface scroll) as their first entry. These need:

  has0aPreface: true    — in the catalog entry
  scrollCount: N        — raw count of book files (including 0a)

The app logic (in data.ts createCatalogVolumes and server.js) handles merging:
  effectiveScrolls = scrollCount - 1   (merges 0a into scroll 1)
  scroll 1 fetches bookIds: firstBookId (0a) + firstBookId+1 (1卷)
  scroll 2+ fetches: firstBookId + scroll

Parts known to have 0a preface (as of 2026-03):
  386, 423, 458, 517, 519


STEP 4: ADD ENTRIES TO data.ts AND server.js
--------------------------------------------
Both files contain a SCRIPTURE_CATALOG array. They MUST stay in sync.

Entry format:
  { part: NNN, title: '經名', subid: NNN, scrollCount: N, firstBookId: NNNN, collectionId: 48 }
  { part: NNN, title: '經名', subid: NNN, scrollCount: N, firstBookId: NNNN, collectionId: 48, has0aPreface: true }

Title: Use the traditional Chinese title from the upstream page <title> tag.
       Format is "第NNN部 TITLE" — extract the TITLE part.


STEP 5: VERIFY EVERYTHING
--------------------------
After adding/modifying entries, run these verification scripts:

  1. node scripts/verify_subids.cjs
     → Checks that each subid maps to the correct part title at upstream

  2. node scripts/verify_bookids.cjs
     → Checks firstBookId, scrollCount, and has0aPreface against upstream

  3. node scripts/verify_content.cjs   (requires iconv-lite)
     → Fetches actual content from the API and checks title match

All 166/166 should show OK.


CORRECTION SCRIPTS (for bulk fixes)
------------------------------------
  scripts/build_correct_mapping.cjs    — Builds correct part→subid map, applies subid corrections
  scripts/apply_bookid_corrections.cjs — Applies firstBookId/scrollCount corrections from bookid_verify_results.json


COMMON PITFALLS
---------------
1. subid is NOT part number. There are skipped subids (484, 486, 573) and
   relocated parts (467→633). Always verify against upstream.

2. bookId is NOT sequential across parts. Always fetch from the page.

3. scrollCount was originally set to 1 for all parts — this was wrong.
   Many parts have multiple scrolls (up to 20).

4. Content API returns GBK encoding, not UTF-8. Must decode properly.

5. Page titles are in traditional Chinese (繁體). Content text may be in
   simplified Chinese (简体). Compare using page titles, not content text.

6. The CATALOG_BASE_URL in data.ts must match collectionId (currently /id/48/).
